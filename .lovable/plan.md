# ระบบสินเชื่อจำนำเล่มทะเบียนแลกเงินสด (Car for Cash) — Phase I

Web application ภาษาไทย รองรับ 11 สาขาในจังหวัดสุราษฎร์ธานี แทนระบบเดิม VB6 + MS Access + Crystal Report

## ขอบเขต Phase I

Core สินเชื่อครบวงจร: ลูกค้า → ประเมินรถ → ขอสินเชื่อ → อนุมัติ (Approver Flow) → ทำสัญญา → จ่ายเงิน → ตารางผ่อน/รับชำระ → ติดตามหนี้ → รายงาน + Dashboard

## โครงสร้างระบบ

Backend ใช้ Lovable Cloud (ฐานข้อมูล + auth + storage + server functions ในตัว) ไม่ต้องสมัครบริการภายนอก

### สิทธิ์และสาขา
- Role: `admin` (สนง.ใหญ่), `manager` (ผจก.สาขา), `approver`, `staff`, `viewer` — เก็บในตาราง `user_roles` แยกจาก profile
- **สาขาเห็นเฉพาะข้อมูลของตัวเอง** สนง.ใหญ่เห็นทุกสาขา บังคับที่ระดับฐานข้อมูล (RLS) ไม่ใช่แค่ซ่อน UI
- รองรับเพิ่มสาขาใหม่ได้จากหน้าตั้งค่า

### โมดูลหลัก
1. **CRM ลูกค้า** — ข้อมูลลูกค้า, ผู้ค้ำ, ที่อยู่, เอกสารแนบ (บัตร ปชช./เล่มทะเบียน/รูปรถ), ประวัติการติดต่อ, ประวัติสินเชื่อทั้งหมด
2. **ทะเบียนรถ/หลักประกัน** — ยี่ห้อ/รุ่น/ปี/เลขทะเบียน/เลขตัวถัง, ราคาประเมิน, สถานะเล่มทะเบียน (รับเข้า/คืน)
3. **คำขอสินเชื่อ** — วงเงิน, ดอกเบี้ย, จำนวนงวด, คำนวณตารางผ่อนอัตโนมัติ, พิมพ์ใบเสนอ
4. **Approver Flow** — คำขอที่ต้องอนุมัติ: อนุมัติสินเชื่อเกินวงเงินสาขา, ลบ/แก้ไขข้อมูลสำคัญ, ยกเลิกสัญญา, ปรับโครงสร้างหนี้ — มีสถานะ รอ/อนุมัติ/ไม่อนุมัติ + เหตุผล + ผู้อนุมัติ + เวลา
5. **สัญญาและการจ่ายเงิน** — เลขที่สัญญาอัตโนมัติต่อสาขา, พิมพ์สัญญา A4 ภาษาไทย, บันทึกการจ่ายเงินให้ลูกค้า
6. **รับชำระ** — รับชำระตามงวด/ปิดบัญชีก่อนกำหนด, ตัดชำระดอกเบี้ย→เงินต้น, ค่าปรับล่าช้า, พิมพ์ใบเสร็จ
7. **ติดตามหนี้** — รายการค้างชำระ, อายุหนี้ (aging), นัดหมายติดตาม, บันทึกผลการติดตาม
8. **Dashboard ผู้บริหาร** — ยอดปล่อยสินเชื่อ, ยอดคงค้าง, NPL, ยอดรับชำระรายวัน/เดือน, เปรียบเทียบรายสาขา, กราฟแนวโน้ม (สนง.ใหญ่เห็นรวม สาขาเห็นของตัวเอง)
9. **รายงาน** — Export PDF และ Excel ขนาด A4 ฟอนต์ไทย: รายงานประจำวัน, สรุปสัญญา, รับชำระ, ค้างชำระ, สรุปรายสาขา
10. **Audit log** — บันทึกทุกการสร้าง/แก้ไข/ลบ พร้อมผู้ทำและเวลา (ทดแทน manual control เดิม)

### สูตรคำนวณ (ค่าเริ่มต้น ปรับได้ในหน้าตั้งค่า)
- ดอกเบี้ยแบบ Flat rate ต่อเดือน (ตั้งค่าเริ่มต้น 1.25%/เดือน)
- ผ่อน 12/18/24/36 งวด, งวดเท่ากันทุกงวด
- ค่าปรับล่าช้าคิดเป็น % ต่อวันของยอดงวดที่ค้าง
- ค่าดำเนินการ/ค่าอากร ตั้งค่าได้
- LTV (วงเงินสูงสุดต่อราคาประเมิน) ตั้งค่าได้ต่อประเภทรถ
> ปรับสูตรจริงได้ภายหลังโดยไม่ต้องรื้อระบบ

### AI ช่วยงาน (Lovable AI)
- สรุปโปรไฟล์และความเสี่ยงลูกค้าจากประวัติชำระ
- ถาม-ตอบข้อมูลระบบด้วยภาษาไทย (เช่น "สาขาไหนยอดค้างสูงสุดเดือนนี้")
- ช่วยร่างข้อความติดตามหนี้/แจ้งเตือนลูกค้า
- ผู้ช่วยสรุป Dashboard เป็นข้อความไทย

### แจ้งเตือน & Webhook (เตรียมพร้อม Phase 1.1)
- ตารางกำหนด event ที่ต้องแจ้งเตือน: ขออนุมัติ/ผลอนุมัติ, วงเงินอนุมัติของลูกค้า, ครบกำหนดชำระ, ค้างชำระ, backup สำเร็จ/ล้มเหลว, ระบบปิดปรับปรุง
- คิวข้อความแจ้งเตือน + แจ้งเตือนในแอป (in-app) ใน Phase I
- Webhook endpoint สาธารณะ (มี signature verification) ให้ n8n ดึงไปส่ง LINE / LINE OA ได้ทันที + ตั้งค่า URL ปลายทางในหน้า setting
- แยกกลุ่มผู้รับ: ลูกค้า / พนักงาน

### Backup & Cycle Management
- งานสำรองข้อมูลรายวัน (export snapshot) + ลบไฟล์เก่าเกิน 1 วันอัตโนมัติ
- หน้าดูสถานะ backup ล่าสุด + สั่ง backup เอง + แจ้งเตือนผลลัพธ์

## แผนการส่งมอบ

1. เปิด Lovable Cloud + วางโครงฐานข้อมูล (สาขา, ผู้ใช้, role, RLS, audit) + ระบบ login
2. Design system ไทย (โทนน้ำเงิน/เหลืองตามแบรนด์ ธารทรัพย์) + layout หลัก + เมนูตาม role
3. CRM ลูกค้า + หลักประกัน + อัปโหลดเอกสาร
4. คำขอสินเชื่อ + คำนวณตารางผ่อน + Approver Flow
5. สัญญา + จ่ายเงิน + รับชำระ + ใบเสร็จ
6. ติดตามหนี้ + Dashboard ผู้บริหาร
7. รายงาน PDF/Excel A4 ภาษาไทย
8. AI ช่วยงาน + ระบบแจ้งเตือน + Webhook + Backup

## รายละเอียดทางเทคนิค

- TanStack Start + Lovable Cloud (Postgres + RLS + Storage + server functions)
- แยกสาขาด้วย `branch_id` ทุกตารางธุรกรรม + RLS policy อิง role/สาขาผ่าน security-definer function
- เลขที่เอกสารใช้ sequence ต่อสาขา/ปี ป้องกันซ้ำ
- PDF ฟอนต์ไทย (Sarabun) ฝังในเอกสาร, Excel ผ่านไลบรารีฝั่งเซิร์ฟเวอร์
- AI ผ่าน Lovable AI Gateway (ไม่ต้องมี API key ภายนอก)
- Webhook อยู่ใต้ `/api/public/*` พร้อมตรวจ signature
- ยอดเงินเก็บเป็นจำนวนเต็มสตางค์ เลี่ยงปัญหาปัดเศษ

## ยังไม่รวมใน Phase I
ส่ง LINE/LINE OA จริง (Phase 1.1 ผ่าน n8n), push notification บนเบราว์เซอร์, การนำเข้าข้อมูลเดิมจาก MS Access (ทำเป็นงานแยกเมื่อได้ไฟล์ตัวอย่าง)
