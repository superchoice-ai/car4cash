## สรุปผลวิเคราะห์ระบบเดิม (จากภาพหน้าจอ TCA)

หน้าจอหลักของระบบเดิมมีปุ่มสองกลุ่มด้านขวา คือ **รายรับ** และ **รายจ่าย**

**รายจ่าย** แยกเป็น 8 หมวด (ปุ่มเหลือง): เงินเดือน · ประกัน · ทะเบียน · ติดตาม · สำนักงาน · ดอกเบี้ย · ต่างสาขา · อื่นๆ  
แต่ละหมวดเปิดฟอร์มย่อยที่มีฟิลด์เหมือนกันหมด: `รหัส` · `ชื่อ-สกุล` · `วันที่` · `เลขที่ใบเสร็จ` · `จำนวนเงิน` (+ หมายเหตุ) พร้อมปุ่ม เพิ่ม/แก้ไข/บันทึก/ค้นหาใบเสร็จ  
หน้า "ลบข้อมูลแฟ้มรายจ่าย" แสดงยอดรวมทุกหมวดในใบเสร็จเดียว และเพิ่มหมวด **คืนเงินกู้** → ยืนยันว่าหนึ่งใบเสร็จรายจ่ายมีได้หลายหมวดพร้อมกัน

**รายรับ** (จากตาราง `legacy_receipts` ที่ import ไว้แล้ว) หนึ่งใบเสร็จแยกช่อง: เงินต้น · ดอกเบี้ย · ค่าปรับ · ค่าติดตาม · ค่าประกัน · ค่าทะเบียน · เงินทอน · รวม  
หน้าติดตามหนี้ก็แยก: ค่างวด · ค่าปรับ · ค่าติดตาม · ยอดปิดบัญชี

จึงยืนยันว่าหมวดร่วม (ดอกเบี้ย ประกัน ทะเบียน ติดตาม) เกิดได้ทั้งฝั่งรับและฝั่งจ่ายจริง

## สิ่งที่จะสร้าง

### 1. ฐานข้อมูล: ตาราง cashbook ตารางเดียว
ตาราง `cash_entries` (หัวใบเสร็จ) + `cash_entry_lines` (บรรทัดแยกหมวด)

- `cash_entries`: สาขา, ทิศทาง (`income` / `expense`), เลขที่ใบเสร็จ, วันที่, ผู้เกี่ยวข้อง (ลูกค้า/พนักงาน/คู่ค้า — เก็บทั้ง `party_name` และ `customer_id`/`contract_id` แบบไม่บังคับ), วิธีชำระ, ยอดรวม, เงินทอน, หมายเหตุ, สถานะยกเลิก, ผู้บันทึก
- `cash_entry_lines`: หมวด (enum) + จำนวนเงิน (สตางค์/bigint) + หมายเหตุ
- enum `cash_category`: `principal` เงินต้น · `interest` ดอกเบี้ย · `penalty` ค่าปรับ · `insurance` ค่าประกัน · `registration` ค่าทะเบียน · `follow_up` ค่าติดตาม · `salary` เงินเดือน · `office` ค่าสำนักงาน · `loan_repay` คืนเงินกู้ · `inter_branch` ต่างสาขา · `other` อื่นๆ
- แต่ละหมวดมี "ทิศทางที่อนุญาต" กำหนดในโค้ด (เช่น เงินเดือน = จ่ายอย่างเดียว, ดอกเบี้ย = ได้ทั้งสองทาง)
- RLS/GRANT ตามรูปแบบเดิม: สาขาเห็นเฉพาะสาขาตน, สนง.ใหญ่เห็นทั้งหมด, ลบต้องผ่าน approver flow (ใช้ `approval_requests` เดิม)

### 2. หน้ารับชำระ — เพิ่มช่องแยกหมวดเหมือนเดิม
ปรับ `src/routes/_authenticated/payments/index.tsx` ให้ฟอร์มรับชำระมีช่อง: เงินต้น · ดอกเบี้ย · ค่าปรับ · ค่าประกัน · ค่าทะเบียน · ค่าติดตาม · เงินทอน โดยยังคง auto-allocation เดิมเป็นค่าเริ่มต้น (กดปุ่ม "คำนวณอัตโนมัติ" เติมให้) แต่แก้ไขได้เอง  
เมื่อบันทึก: สร้าง `payments` เดิมตามปกติ **และ** สร้าง `cash_entries` ทิศทาง `income` พร้อมบรรทัดแยกหมวดอัตโนมัติ (ผูก `contract_id`) — ไม่กระทบ logic ตัดงวดเดิม

### 3. หน้ารายจ่าย (ใหม่)
`/finance/expenses` — ตารางรายการ + ฟอร์มบันทึกแบบใบเสร็จเดียวหลายหมวด (ตรงกับหน้า "แฟ้มรายจ่าย" เดิม), ค้นหาตามเลขที่ใบเสร็จ/ชื่อ/ช่วงวันที่/หมวด, แก้ไข, ขออนุมัติลบ  
ใช้ pattern เดิม: `PageHeader`, `StatusPill`, `EmptyState`, การ์ดสรุปยอด, ตาราง shadcn

### 4. หน้าสมุดรายรับ-รายจ่ายรวม
`/finance` — มุมมองรวมทั้งสองทิศทาง กรองตามวัน/เดือน/สาขา/หมวด พร้อมสรุป รับ − จ่าย = คงเหลือ

### 5. รายงานชุดเดิม (เมนู "รายงานผล")
เพิ่มที่ `/reports` เป็นเมนูรายงานแบบเดิม แต่ละรายการพิมพ์ A4 ภาษาไทย:

- รายงานเฉพาะบุคคล
- สรุปรายรับประจำวัน / เดือน
- สรุปรายจ่ายประจำวัน / เดือน
- ลูกค้าปิดบัญชี
- สรุปยอดบัญชีแยกประเภท
- บัญชีลูกหนี้ · บัญชียอดคงเหลือลูกหนี้ (ลูกหนี้ทั้งหมด / ลูกหนี้สรรพากร → ลูกหนี้, ลูกหนี้คงเหลือ, รายรับ, ลูกหนี้ปิดบัญชี)
- บัญชีลูกหนี้ค้างชำระ 1–2 / 2–3 / เกิน 3 เดือน
- จ่าหน้าซองจดหมาย (ค้างชำระ 1–2 / 2–3 เดือน)
- บัญชีเงินลงทุน − คืนเงินกู้
- รายได้ค่าประกัน · รายได้ค่าทะเบียน
- ใบปะหน้าติดตาม · รายงานค่าติดตามหนี้ · รายงานบันทึกการติดตาม
- รายชื่อลูกค้าที่ไม่ต้องการ (blacklist)
- รายรับต่างสาขา · รายรับอื่นๆ

โครงสร้าง: `/reports` เป็นเมนูรวม + route ย่อย `/reports/$reportId` ที่ render ตาม config เดียว (หัวกระดาษ ธารทรัพย์ + สาขา + ช่วงวันที่ + ตาราง + ยอดรวม + ที่ว่างลงนาม) เพื่อให้ทุกใบหน้าตาเหมือนกันและเพิ่มรายงานใหม่ได้ง่าย  
รายงานที่ยังไม่มีข้อมูลรองรับ (เช่น เงินลงทุน) จะดึงจาก cashbook หมวดที่เกี่ยวข้อง

### 6. Dashboard
เพิ่มการ์ด รายรับ/รายจ่าย/กำไรขั้นต้น ประจำวันและเดือนปัจจุบัน แยกสาขา

## รายละเอียดทางเทคนิค

- จำนวนเงินเก็บเป็น `bigint` หน่วยสตางค์ ตามระบบเดิมทั้งหมด ใช้ `formatMoney` จาก `src/lib/format.ts`
- เพิ่ม `CASH_CATEGORY_LABEL` และ `CASH_DIRECTION_LABEL` ใน `src/lib/labels.ts`
- เพิ่ม `src/lib/cashbook.ts` เก็บ config หมวด/ทิศทาง/ลำดับการแสดงผล และตัวช่วยรวมยอด
- เพิ่ม `src/components/PrintReport.tsx` เป็น layout A4 กลาง (`@media print` มีอยู่แล้วใน styles.css)
- import ข้อมูลเก่า: map `legacy_receipts` → `cash_entries` ทิศทาง income (มี field ตรงกันครบ) เพิ่มเป็น dataset ใหม่ใน `src/lib/legacy-import.ts`
- ลำดับงาน: migration ฐานข้อมูล → lib/labels → หน้ารายจ่าย + cashbook → ปรับหน้ารับชำระ → ชุดรายงาน → dashboard
